重复别名兼容修复及验证（2026-11-13）

修改位置：E:\project\seekdb-query-optimization
生产代码：cpp/query.cpp
回归测试：tools/test_cpp.py 的 duplicate_alias_ordering
缓存边界差分测试：boundary_check/duplicate_alias_budget.py

原问题
SELECT id,L2_DISTANCE(v,[0,0]) AS x,L2_DISTANCE(v,[10,0]) AS x
FROM t ORDER BY x LIMIT 1;

在原复现数据中，Python f1b9f4e 返回 id=1，修复前 C++ 返回 id=2。
本次以用户指定的 Python 版本为标准修正 C++，不是把歧义别名定义为 MySQL 标准行为。

修复后的实际响应
无索引：两版均返回 columns=["id","x","x"]，rows=[[1,0.0,10.0]]。
有索引：两版均返回 columns=["id","x","x"]，rows=[[1,0.0,10.0]]。
之前 4 种 SQL 在有/无索引下的 8 处别名差异全部消失。

修复规则
Python 普通排序解析到最后一个同名别名；向量校验和索引/缓存候选路径取第一个。
C++ 现在保留这两种行为，并按实际排序表达式复用距离值，避免投影中两个 x 的
距离值也被错误复用。LIMIT 0、空结果、VECTOR 别名的校验时机同时对齐。
当两版缓存容量不同，C++ 根据通过版 Python 3.12/NumPy 的预算规则选择表达式，
不再因为 C++ 连续数组能缓存更多/更少记录而改变重复别名的查询结果。
该预算兼容逻辑仅用于第一个与最后一个表达式不同的距离别名歧义；可能额外遍历
缓存标量或数据行。普通无歧义查询不执行这项预算检查。本轮未进行性能评分。

缓存专项包含：
1. 从 90,000 行增至 100,000 行：Python 缓存由可用转为超预算，C++ 缓存仍可用。
   两版都从第一个距离表达式的 id=1 切换为普通排序最后一个表达式的 id=2；
   创建索引后，两版重新返回 id=1。
2. 4,000 行、每行 3,000 个 Latin-1 字符：Python 紧凑字符串缓存可用，C++ 的
   UTF-8 字符串缓存超预算。两版依旧返回相同 TopK，距离投影也一致。
