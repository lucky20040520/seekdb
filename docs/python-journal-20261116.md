# Python exact：距离、JSON 与提交路径优化（2026-11-16）

本轮完成三项改动，保留 Python 3.12.8、NumPy 1.26.4 和 exact 语义。本轮基线是开始修改时的 `minivector-python:exact-screen-20261116` 镜像，包含上一轮尚未提交的优化，**不是干净的 HEAD 8ec857e**。最终镜像为 `minivector-python:bounded-journal-20261116`。所有结果为 E_local，不能视为官方成绩或隐藏 MySQL 准入结论。

1. 距离计算缓存 float64 平方范数，通过 NumPy 矩阵向量乘法筛选候选；最终距离仍用原 Python `math.sqrt(math.fsum(...))` 精算，按距离、主键排序，先过滤后 TopK。范数计入原 16 MiB 缓存总预算，没有增加一份分组向量副本。16～4096 维、至少 128 行且预算足够时启用；过滤向量临时复制限 1 MiB，超过时计算已有矩阵后选择过滤行。范数相消、候选过多、非有限中间值或预算不足时回退原精确路径。
2. JSON 输出对估计编码大小不超过 64 KiB 的简单行使用 `json.dumps`，大行仍流式编码。`ensure_ascii=False`、`allow_nan=False`、紧凑分隔符、整数和浮点表示、Unicode、字段顺序、每个响应一条物理行均保持。完整响应仍先写入 256 KiB 上限的内存/磁盘 spool；惰性查询异常不会向 stdout 留下半条成功响应。
3. 普通写入将不可变行段和目录增量追加到同一个日志文件。DATA/COMMIT 帧包括类型、长度、SHA-256 和尾部封印，完整 COMMIT 才发布此前数据，随后 fsync 完成才能响应成功。正常无索引的 100 次批量提交，独立 profiling 中 fsync 从 400 次降到 100 次。磁盘索引及独立行文件仍先同步内容和目录项，再同步目录提交；大表重写不套用单次 fsync 的结论。

保守筛选边界是绝对误差界，避免把范数相消后的距离当作相对误差基数。对维度 d、扫描值 S 和精确平方距离 D，使用：

```text
e = (d + 4) * eps32
gamma = e / (1 - e)
E = 8 * gamma * (max_norm + query_norm) + 8 * d * tiny32
|S - D| <= E
候选：S <= nextafter(kth(S) + 2*E, +inf)
```

点积误差由 `gamma * sum(abs(x_i*q_i))` 控制，且 `2*sum(abs(x_i*q_i)) <= ||x||²+||q||²`。实现额外覆盖范数累加、float64 阈值和下溢误差。最终排序只使用精算距离。异常幅度、相消、近似并列、重复向量、过滤集合及事务可见性均有与独立标量全量真值逐项比较的测试；没有采用 ANN。

日志通过 `CURRENT` 指定当前代。达到 8 MiB 且无效空间达到 `max(4 MiB, 活跃段大小/2)` 时，同步复制活跃段并原子发布新代；先同步新文件及目录，替换 CURRENT 后再次同步目录，最后回收旧代。索引中的段位置同步重映射。提交同步失败会保留文件并拒绝继续写入，待重启决定是否恢复完整但未获响应的提交。恢复只接受封印和校验均完整的目录提交，尾部未提交数据可重复截断。旧 catalog/JSONL/二进制段仍可读取；旧版引擎不能直接写入新日志目录，回退旧引擎须使用旧数据快照。

低内存复测暴露了初版日志在大表重写上的长尾，因此当被重写表的原始负载超过 8 MiB 时，改用独立不可变二进制段；普通追加批次仍用日志。该选择只改变存储路径，提交、回滚、索引和恢复语义保持。恢复测试覆盖所有字节截断位置的双表事务、校验损坏、语句失败、fsync 失败、checkpoint 各边界真实强杀，以及恢复过程中再次强杀。

测量固定 10,000 行、128 维、1,000 次查询、K=10、两组过滤各 500 次、每批 100 行提交。每种场景三轮交替运行基线、距离＋JSON中间版、最终版；全部关闭 profiling。写入/查询使用独立容器、数据卷和父 cgroup。查询装载、建索引和预热计入 B/M；进程退出后继续统计至 syncfs 完成、无脏页/写回且 I/O 稳定。所有真值与重启验证均在采集结束后进行。每轮六项指标计算 E 后再取中位数；下表各指标中位数仅用于展示，没有拼接最优值。
