# 诊断协议进程管道验证

公开SQL现通过tools/run_stdio_public.py启动真实数据库子进程，逐条写入SQL后flush，故意不发送换行，读取成功/错误/列名/记录/结束标识，再复用公开断言比较。stderr并行排空，读取超时明确失败。每例独立目录，--restart用EOF正常关闭、等待退出后复用目录。

实际复现：修复前Windows仅14/40重放通过，主要中文输入被默认编码误读并产生后续状态失败。新增cp1252默认编码的中文+emoji反例，修复前失败。父进程encoding不能配置子进程；程序入口改为显式UTF-8。修复后49项自建检查通过，exact及ann启动模式各20例，共40/40重放、190条SQL通过；公开资产哈希不变。

模式边界：目前每种启动模式完整重放一次；公开--mode指令不作为SQL发送，也没有通过重启假装事务内模式切换。两次重放验证两条启动入口，但不等于正式在线模式切换协议。LOCAL_READY/OK/TSV/END仍是自建诊断格式。

此记录是Windows实际结果，提交后另观察Linux容器步骤；不能把未来CI当作已执行。官方分支复查仍为9f6df2ba5acf871376e22b64a3d0724e4b575044，README仍注明不含完整运行驱动。
