## 瓶颈依据与改动

BENG 的 whitespace tokenizer 原先对每个字符都调用 `ob_mbcharlen_ptr`，
ASCII 字符的长度在 UTF-8 下已确定为 1。现在在打开输入时识别 UTF-8，
扫描 ASCII 时直接前进一字节，高字节及其他编码仍调用原字符集函数。
分隔符判断、非法序列处理、token 内容、频率和结束状态保持原规则。

IK 的处理器顺序固定为 letter → quantifier → CJK → surrogate，原实现每个字符
遍历四节点链表并虚调用。本轮改为四个具有明确类型的处理器成员指针和直接调用，
保留执行顺序及出错即停止的行为，省去链表节点分配、遍历与间接调用。
部分构造失败及析构统一释放成员，清空指针，保留字典 hub 的共享所有权。

IK 多个处理器还逐字符调用只读取字段的上下文函数，例如 cursor、is_last、fulltext。
这些短函数现在在头文件中定义，以便当前 Release 编译设置内联；字符解码与状态推进
算法保持原实现。此前采样已观察到 IK 字符处理和分词内存开销，本轮以调用结构和
完整基准进一步验证，未据稀疏采样声称某一函数占据精确 CPU 百分比。

检查中同时修复了此前停用词优化中的缓冲区生命周期问题：跨编码转换的临时
allocator 在 lookup 前可能析构。现在在缓冲存活期间完成查询；UTF-8 的不同
collation 使用同一编码，直接按停用词表的 collation 查找，省去冗余转换路径。
该别名行为与 `ObCharset::charset_convert` 在相同编码下的原行为一致。

## 正确性验证

Release 增量构建成功。29 项生产依赖链接的原生 FTS 测试全部通过，包括：

- whitespace 扫描对照原通用算法，覆盖所有 256 个单字节、随机字节文档、NUL、
  控制字符、标点、Unicode、截断/非法序列、8 KB 输入和 reuse；覆盖此版本支持的
  UTF8MB4_BIN、GENERAL_CI、UNICODE_CI 与 BINARY。该版本未实现 GBK/Latin1。
- 停用词检查与存活缓冲区的字符集转换参考实现对照，覆盖不同排序规则、BINARY
  转换、大小写、CJK、非 ASCII、NUL 与 8 KB 词。
- 既有归并顺序/分值/reuse、字典、正规化、字符分类及词聚合回归。

新增 `fts_pipeline_regression.sql` 包含 73 份固定语料，包括混合语言、歧义词、
量词、全角字符、补充平面字符、emoji、控制字符与确定性随机组合。
70 份正常输入核对 IK SMART/MAX_WORD、BENG 完整 TOKENIZE 输出，再构建索引
核对文档 ID 和真实分值。三个长输入在对照版本的两种 IK 模式下均返回 1210，
作为六个明确的错误路径用例保留，并同时核对长输入 BENG 输出。

回归工具使用 `--force` 收集全部语句的输出；**只允许六个指定长 IK 语句位置的
1210 错误**，其他错误均失败。候选必须与参考的 stdout 和 stderr 分别逐字节一致。
这六个既有错误并未被算作成功分词，也未声称修复了这些长输入的功能问题。
正常输入的索引验证在独立的正常语料集合上进行。官方性能数据始终为完整 20,000 行。
