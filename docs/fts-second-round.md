# 全文索引第二轮优化

起点：`75a4f9f0fa318b7e41ec8f9cd10f8f611416ce1c`。
用户提供该提交的统一评测结果为综合提升率 19.9263%、性能分 39.8525。
该分数与本地旧 baseline.json 不匹配，因此后续以该实际评测为准，
本地只进行相同机器、参数、构建方式下的版本对照，不修改官方评分材料。

## 实现与定位依据

`ObBasicEnglishNormalizer::get_next` 原来对每个词调用通用 `ObCharset::tolower`。
该实现即使输入已经是小写，也会复制到 allocator 并调用字符集转换函数。
现对 UTF8MB4 的纯 ASCII 词识别是否需要转小写：无需转换时借用输入流的
有效 token，有大写时分配并转换；非 ASCII 和其他字符集仍走原实现。
token 的有效期仍为下一次 get_next/reuse/reset 之前，输入不被修改。

`ObAddWord::groupby_word` 原来先 get_refactored，再 set_refactored。
后者会再次计算哈希、遍历桶，且在更新命中词时分配替代节点并释放原节点。
现使用既有 set_or_update 接口，一次查找完成插入或原地更新。
更新时仍替换为最新的 key，以保持排序规则等价但字节不同的 token 的输出。
首次出现仍记为 1，后续才加 word_freq，完整保留已有规则。
未启用 grouping 时仍使用原 set_refactored，包括重复词的 OB_HASH_EXIST。

TOKENIZE 的 20 次 GDB 中断采样观察到 IK 仲裁、字符处理、排序链和 JSON 打包。
这些是定性定位依据，不能推断 CPU 百分比。检查仲裁器发现 `chains_` 是解析器
实例私有的文档暂存表，但默认使用桶锁；现只对该私有表使用 NoPthreadDefendMode。
共享字典的同步方式不变。采样结束后才进行计时，采样摘录一并保存。

## 验证

完整生产 Release 编译成功。原 18 个回归及新增 7 个用例全部通过，共 25 项：

- 英文正常化与通用转换对照：全部 ASCII 字节、1000 个随机词、大小写、
  内嵌 NUL、长词、重音字母、中文、emoji、非法字节、reuse，以及 binary 回退。
- 词频聚合：大小写不敏感等价词保留最后 key、非单位词频首次计数规则、
  碰撞密集的 100 个词多轮更新和遍历顺序、关闭 grouping 的重复词错误。
- IK 仲裁：SMART/MAX_WORD 路径的文档私有词链、reset 后重建、无词链时中文
  单字输出与标点过滤。

使用生产依赖链接的原生测试驱动运行，未运行完整 Bazel 套件。

## 补充服务端循环

为区分客户端往返与分词成本，另外使用服务端 BENCHMARK 循环 TOKENIZE。
输入为原 benchmark 的 IK/BENG 文本，通过用户变量传入；每次循环重新求值，
原版/候选交替启动三对实例，全部固定到同一 vCPU 2。没有编译或调试任务重叠。
每项依次执行 500 次预热、1000 次及 10000 次，循环增长时耗时增长，结果均为 0。
使用同一专用实例目录，相同参数；客户端启动开销未扣除。

| 10000 次耗时（秒） | 原版三次 | 候选三次 |
| --- | --- | --- |
| IK | 0.527668, 0.762690, 0.628799 | 0.599858, 0.486450, 0.468479 |
| BENG | 0.188860, 0.188878, 0.207155 | 0.382640, 0.156987, 0.151769 |

三次中位数分别下降 22.64%（IK）、16.88%（BENG），但第一对均退化，仍有
明显离群值。这只是补充的分词路径测量，不能替代官方全量指标或用来评分。
全部循环次数与结果保存在 focused-tokenize-result.jsonl。

因此本次作为待统一 CI 复测的候选提交，保留 75a4f9f0f 所在原分支；
没有宣称满分或稳定提分。
