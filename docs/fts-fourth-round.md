## 依据与实现

上一轮查询采样观察到逐文档归并、复制和分值计算，EXPLAIN 中计数查询仍为
`calc_relevance=true`。例如 `SELECT COUNT(*) ... WHERE MATCH(...) AGAINST(...)`
只需判断文档是否命中，却仍初始化文档总数/词频统计、平均文档长度、BM25
表达式和分值输出。这里的优化目标是去掉查询不消费的分值计算，保留完整的
分词、倒排扫描、命中去重和过滤语义。

优化器只在可证明安全的自然语言扫描中关闭打分：单表、无子查询、无 boost，
MATCH 仅作为独立 WHERE 真值条件，且没有列投影、其他列过滤、GROUP BY/HAVING
或相关度使用。当前保守地让返回 ID/回表、分值输出、数值阈值、排序、JOIN、
布尔模式及不确定的表达式继续使用原路径；没有按查询文本、词或数据集硬编码。

自然语言模式、无 boost 时，BM25 的 IDF 有正数下界，匹配词的文档权重为正，
因此有命中文档的布尔值为真。不需要数值分值的扫描可以只输出文档标识。
参数改变、空词、停用词、NULL 和空表仍由原分词及扫描路径决定结果。

主要修改：

- 将上述使用情况传递到代码生成，省去分值表达式、冗余真值过滤及统计子扫描。
- 合并器不再无条件解引用文档统计参数，词迭代器不再为无打分查询估计词频；
  允许没有打分 skip 缓冲的 ID 批次，并保护 reuse、范围重设和标量分值投影。
- 常规短词列表继续 DAAT 归并；超过 256 个词仍使用既有 TAAT 分区/落盘路径。
  无 BM25 统计时使用原有最大分区数，并将重复文档按集合去重。
- 有分值需求的查询继续使用原有 BM25 表达式和初始化流程。
