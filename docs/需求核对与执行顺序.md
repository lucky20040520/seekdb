## 一、已经明确、可以直接实施的要求

| 范围 | 明确要求与验收含义 | 题面位置 |
|---|---|---|
| 运行边界 | 单机、单进程、单客户端；同一时刻最多一个显式事务。不能自行扩展为并发数据库再承担额外复杂度 | 2.1 |
| 表结构 | CREATE TABLE；BIGINT、VARCHAR(n)、VECTOR(n)；每表一个BIGINT主键、至多一个向量列 | 2.1 |
| 增删改查 | INSERT/SELECT/UPDATE/DELETE；多行INSERT；按主键或条件更新和删除；投影、星号、五种比较、AND、排序和LIMIT | 2.1 |
| 输入约束 | 主键唯一；字符串长度按Unicode字符计、按码点排序；向量固定维度、存储为float32，拒绝非有限数、溢出和维度错误 | 2.1 |
| 精确向量查询 | L2为欧氏距离；过滤之后取TopK；不足K返回全部；并列按主键升序。普通排序并列也按主键升序 | 2.2 |
| 模式隔离 | 默认exact；建了索引也不能破坏exact正确性。ann模式针对向量TopK，具体接口另定 | 2.2 |
| 持久化 | 表定义和行数据写入/data，正常重启一致；不能依赖把全部数据载入内存来处理超过内存限制的数据 | 2.3 |
| 事务语义 | 自动提交；BEGIN/COMMIT/ROLLBACK；普通查询和向量查询均读己之写；失败语句不得部分修改，之前成功语句仍可提交或回滚 | 2.3 |
| 回滚与提交 | 回滚恢复内容、可见集合及向量结果；成功确认提交前完成持久化 | 2.3 |
| 崩溃恢复 | 进程强杀模型；确认提交保留、未请求提交回滚、请求但未确认允许全有或全无；恢复中再次强杀也应正确；不要求抵抗断电或外部文件损坏 | 2.3、3.2 |
| 实现限制 | 存储、执行、索引及事务核心自行实现；不能让SQLite/RocksDB或Faiss/VSAG/HNSWlib代执行；通用文件、数学、序列化和SQL解析库原则上允许 | 2.1 |
| 进程接口 | Linux x86_64容器、前台、stdin SQL、stdout结果、stderr日志；禁网、不监听端口、及时flush；正常关闭处理未提交事务 | 3.1 |
| 提交 | 报名seekdb仓库的2026-competition-round2分支；源码、Dockerfile、单个学习JSON在同一commit；如填写SHA使用完整值；附设计和运行说明 | 4.1–4.4 |
| 学习材料 | 默认agent/conversation.json；UTF-8对象、最多128KiB、合法标准JSON；原始学生贡献和实际结果直接放在JSON内；无密钥、不捏造对话/实验/理解 | 3.4、4.4 |

不要求的SQL能力也有明确范围：NULL、JOIN、聚合、子查询、ALTER、外键、嵌套事务、主键更新。应明确报不支持，不应静默变成其他操作。

| 分帧、结果格式、就绪标识、错误、模式切换、退出 | 3.1指定以分支配套驱动和题包为依据 | LOCAL_READY/OK/TSV/END/--mode都是自选诊断约定，不称官方格式 |
| 重启、强杀等驱动操作 | 3.2由配套测试定义 | 核心可先按已明确崩溃语义独立验证，正式调用方式待对接 |
| 固定资源、镜像、依赖范围、超时和规模 | 3.1要求统一冻结；2.1保留具体依赖范围；3.3也要求冻结基线与测量工具 | 自建1CPU/256MiB和64MiB进程上限不是官方限额 |
| 近似索引的最终要求 | 2.1保留给题包；2.2描述进阶索引；3.2列有近似检索与维护检查 | 不能擅自称“必做HNSW”，也不能断言“完全不需索引”；精确扫描登记不是已验证的正式索引能力 |

“题包”不必是ZIP，也不必所有文件齐备才能开发。这些接口约定若由官方文档或组织方明确答复给出，同样可用于对接。当前缺失影响的是相应的兼容性及正式验收结论，不是所有功能实施。

## 三、评分与80分目标

1. 全部正式MySQL用例通过是两项计分共同门槛；自建检查或部分用例不能替代。
2. 性能、学习材料分别排名，各最高40分。80分需要两榜都获得40分，不是功能完成就自动得到。
3. 性能可选exact或ann；有过滤和无过滤两组分别满足Recall门槛。不能把题面默认10,000行/128维/1,000查询/K10等同于全部冻结资源配置，也不能把自建旧基线加速比换算为排名。
4. 学习评价看真实学生贡献；Agent自动给出的规划、实现、解释和日志不直接证明学生理解。不能为满分编造学生判断。
5. 按用户最新提供的平台规则，只在同队两项总分提高时整条替换，不拼接不同提交，不需手动选版本，比赛期间是暂定榜；初赛已得分不受影响。
