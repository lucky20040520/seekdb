# 从 powercontext 迁移的方法

来源：本机历史聊天「powercontext」末尾的用户反馈及复盘，2026-11-09 读取。以下是 Agent 的总结，不冒充学生发言，不把旧题运行结果作为新题验证。

1. 真缺陷不等于零分主因。此前发现字体、Form、特殊字号问题后持续深化，未优先证明它们解释失败。新题每次修复必须关联必测项和能复现失败的输入。
2. 广度覆盖在先。此前合法间接引用、损坏压缩流分别覆盖，却漏掉二者组合。新题必须交叉验证事务 × 向量更新 × 回滚 × 重启，以及批量输入 × 后部失败 × 语句原子性。
3. 链路和质量分别验收。此前全文提取成功不能证明证据召回达标。新题 SQL 返回正常不能证明持久化、向量可见性或过滤 TopK 正确。
4. 独立真值优先。用过滤后的数据独立暴力计算 float32 存储值的欧氏距离，避免被测索引自己验证自己。崩溃测试由外部进程观察响应并强杀。
5. 反馈推翻假设。收到零分时重新检查所有硬门槛，比较已知通过和失败版本的同一组测试；不能只增加当前方向的自建测试。
6. 保留通过版本。可选优化先在独立版本验证，完成全矩阵回归后再替换。公开通过与正式通过分开表述。
7. 学习记录保持真实。学生原话、Agent 提议、工具输出分来源记录；Agent 代写的技术总结不能当作学生理解。不得编造实验或将旧题结果套到本题。
