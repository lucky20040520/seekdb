## 1. 目标及计分的三层关系

这是从零实现数据库的加赛，不是修改seekdb内核来调用已有引擎。seekdb仓库是要求的提交载体。允许一般文件/数学/序列化/SQL解析库，但存储、执行、索引、事务核心不能委托给现成数据库或向量引擎。

第一层是功能准入：全部正式MySQL case及其中全部断言通过，无崩溃、超时或资源超限。功能不单独给分；一个必测失败，两项加赛成绩均不能计分。

第二层是两个独立有效性检查：功能准入后，性能结果不合格只影响性能榜；学习材料不合格只影响学习榜。两项必须属于同一次锁定提交，不能拼接。

第三层才是独立排名：每榜第r名折算max(40-0.5*(r-1),0)，并列跳过后续名次。拿到加赛80分需要两榜均获得40分，不能以功能完成、达到召回门槛或本地提速代替两榜排名。

总赛分为原有实际得分加这两项，620是原有部分上限，不是默认发放的基础分。加赛失败不清零已有题目得分。材料中“预赛前50名无需参加”的免赛表述，应按赛事通知确认适用条件，不能据此假定本用户具备资格。

## 2. 功能要求的准确含义

| 项目 | 题目要求 | 常见错误理解 |
|---|---|---|
| 范围 | 单进程、单客户端、最多一个显式事务 | 不需要先开发并发控制、分布式或完整SQL |
| 表结构 | 一个BIGINT主键、最多一个向量列；VARCHAR(n)和VECTOR(n) | 不是任意类型、任意维度都接受 |
| 普通查询 | 投影、星号、五种比较、AND、排序及LIMIT；更新删除支持条件 | 不能仅按主键点查或仅支持单行INSERT |
| 字符串 | Unicode字符数量限制和码点排序 | 不是UTF-8字节长度，也不是拼音/本地语言排序 |
| 向量 | 固定维度有限float32；拒绝NaN/Inf/转换溢出 | 输入能转成Python float不代表能合法存入float32 |
| 精确TopK | 基于存储后的向量计算欧氏距离；先过滤再排名；距离并列按主键升序 | 不是平方距离输出，也不能先全局取K再过滤 |
| 排序 | 普通ORDER BY并列也用主键升序；无ORDER BY按集合比较 | 不能把插入顺序当作并列规则 |
| 自动提交 | 无BEGIN时每条成功修改独立持久化 | 不能把所有修改等到进程退出再写盘 |
| 显式事务 | 普通查询及向量查询均读到事务内成功修改 | 不能仅更新表而继续查旧向量缓存 |
| 语句原子性 | 失败语句无部分修改，之前成功语句继续有效 | 不能只做到整事务回滚而没有语句级原子性 |
| 回滚 | 内容、可见集合及向量结果均恢复 | 不能只把行数恢复或只恢复一个存储副本 |
| 崩溃恢复 | 确认提交不丢，未请求提交不生效；请求未确认全有或全无；支持恢复中再次强杀 | 不能用正常关闭重启代替强杀检查 |
| 大数据 | 数据超过内存预算仍可处理，恢复和索引准备成本也受限 | 默认性能负载较小不代表可以全部常驻内存 |
| 不支持能力 | NULL/JOIN/聚合/子查询/ALTER/外键/嵌套事务/主键更新不要求 | 不支持时要报错，不能静默执行为其他语句 |

例：WHERE筛选B组、K=2，全局最近两行都属于A组，而B组还有两行。正确结果是B组内部最近两行，不能返回空集。

例：BEGIN后先成功插入主键1，再执行一条包含主键2和重复主键1的多行INSERT。后一句须完全失败；此时COMMIT只保留此前主键1，不能留下主键2，也不能自动撤销之前成功的那句。

例：事务中修改向量后再ROLLBACK。普通SELECT、精确检索、索引路径及缓存路径必须共同恢复；只分别测“更新”和“回滚”不能证明组合正确。

## 3. 精确检索与索引不能混淆

exact是默认模式，建索引也不能把exact悄悄改成近似。性能负载明确允许exact或ann，因此不是必须用HNSW才能获得性能成绩。

同时，题面描述进阶CREATE VECTOR INDEX，并在功能测试分类中列出近似检索和索引维护；最终索引要求仍留给统一题包。因此不能反向推定“只要精确扫描，所有索引必测必然通过”。当前代码接受建索引语句并保留描述、使用精确扫描，只能据此证明现有路径结果，不应宣布正式索引验收完成。

## 4. 性能门槛与目标

默认负载为10,000行、128维、1,000条TopK查询、K=10，一半带等值过滤。写入每批100行并提交。数据使用正式未知种子，不能预存答案。无过滤、有过滤两组的平均Recall@10各自至少0.95，不能用合并平均掩盖其中一组失败。

正确性、持久化及资源约束都要成立。精确算法可使召回正确，但仍可能因时间、I/O、内存或索引准备超限失效。

写入、查询各自按耗时60%、I/O20%、内存20%计算归一化指标，整体查询权重是写入的两倍。每轮分别算综合指标，再取三轮中位数，不能拼接不同轮次的最佳T/B/M。

查询计时可以不含索引准备，但资源统计包含启动、装载、构建、预热和写回；M包含文件页缓存，B是物理读写，不是文件大小。当前本地耗时、缓存估算量、进程RSS或RLIMIT_AS均不能替代正式cgroup测量。

## 5. 学习材料与评分对象

真实记录应随着做题保留，不能最后补造。默认路径agent/conversation.json，单个UTF-8顶层对象、最多128KiB；源码、Dockerfile和材料在同一commit。需要评价的原话与具体结果直接放入JSON，外部文件链接不是证据替代品。

详细题面采用agent-learning-evidence-v3-unbounded：按独立问题/实验/修正链去重，实例分0.5/1/1.5/2四档；评审三次，各维度取中位数后相加。原始分只决定排名，并非比赛40分上限。Agent自动完成代码和验证不等于学生贡献，不能用对话长度、测试数量或编造的质疑提高评价。
