# 磁盘Flat L2索引：功能补齐

本次补齐CREATE VECTOR INDEX的实际索引、维护与恢复，不将近似算法设为性能准入前置条件，不做性能冲榜。

## 实际索引结构

`minivector/flat_index.py`自行实现不可变二进制Flat L2索引，无第三方向量索引库。每个数据段对应一个`index-*.flat`文件，保存在数据库数据目录（容器为/data）。

16字节头保存格式标识、向量维度和向量列位置；每条索引记录保存int64主键、uint64原始行字节偏移及float32向量，长度为16+4×维度字节。索引描述中的segments把数据段名映射到同一不可变版本的索引文件。

向量排序查询在有索引时实际读取这些文件，过滤条件在候选进入TopK前判断；堆中保存距离/主键/位置而非整条宽记录，最后按位置回查当前记录。大结果排序仍走外部归并。距离以float64运算和math.fsum计算，使用欧氏距离及主键并列规则。

exact和ann入口目前都可使用这条精确Flat路径。它是真实磁盘索引，但不是HNSW/IVF之类近似剪枝算法；不宣称已实现近似加速、已满足未冻结ANN时间/资源限制或取得性能排名。

## 索引维护与事务

- CREATE在完成现有数据段的索引写入及fsync后才发布描述；空表可以先建索引，后续新增段再物化索引。
- INSERT为新段创建索引，保留旧段索引；UPDATE/DELETE为替换段重建相应索引。
- 数据文件、主键文件及索引文件先完成同步，最后通过同一提交清单原子发布。普通数据及索引不独立提交。
- 显式事务保存独立清单，查询立即使用事务可见的索引版本；ROLLBACK恢复已提交清单并清理未引用文件。
- 索引构建失败不会发布部分语句；新建行文件和索引文件均清理，之前的成功状态保留。

## 启动与重复恢复

启动读取已提交清单，清理未引用文件，再验证索引头、记录宽度及主键侧文件对应的记录数。旧版本exact_scan描述、缺失或不完整的派生索引会从持久化行数据流式重建；重建并发布完成后构造函数才返回，CLI随后才输出LOCAL_READY。

这是针对题面进程强杀模型的恢复流程，不承诺抵抗任意外部篡改或断电损坏。缺失索引和旧描述的构造测试用于验证派生数据可重建。

## 实际验证

Windows：48项自建检查通过（8.927秒），官方20例/95条SQL核心层断言仍全部通过，公开资产未修改。

新增索引专项检查覆盖：实际文件与实际查询路径、六种列顺序、修改/删除/插入、回滚文件清理、提交和重启、构建失败原子性、事务内建索引回滚、旧描述/缺失索引重建、40步随机事务与未建索引表的240组查询对照。

强杀检查包括：维护索引文件写完但未发布时强杀；启动重建连续两次在写完派生文件后强杀，确认此前没有就绪输出，最后正常启动可查询。原有提交清单切换前/后强杀检查也加入了物理索引。

容器资源检查新增`--with-vector-index`：在64MiB进程地址空间中通过SQL批次载入大表，再构建、查询、修改/回滚、删除/提交和重启磁盘索引。该扩展需观察本次CI结果，不能沿用旧的无索引压力结果冒称通过。
