# Python 性能优化方案与验证

已完成 Python exact 查询、输入解析和二进制存储优化。最终 E_local 为无索引 0.635468、有索引 0.779541；全部最终 6000 次 exact 查询正确。默认 `Dockerfile` 启动 `python -m minivector`，依赖保持 Python 3.12.8 / NumPy 1.26.4；不引入自行编译的原生引擎。此前 C++ 实验保留在独立 `Dockerfile.cpp`，不作为本轮优化结果。

## 基线与功能约束

基线源码为 `f1b9f4e204f08f5043b315ba1ebec500ad7af255`。历史提交 `bf7afb70ed0d84fa3e19ea5130a6f7e0b88bba6a` 的 `agent/conversation.json` 中 `formal-python-f1b9f4e` 记录了用户提供的平台正式 MySQL 用例通过反馈；这属于历史反馈，不能证明新改动已经正式准入。

使用已经冻结的 Python 镜像 `minivector-baseline:python-20261114-175804`，以及无索引、有索引两组各自三轮的六项指标基线。保留 SQL 解析与错误语义、float32 舍入、过滤后 TopK、主键破并列、事务可见性与清单持久化顺序。不得为提速放宽真值检查或跳过必要 fsync。

`Dockerfile.python` 使用当前工作区源码，只是 Python 构建入口的副本，不代表冻结基线；恢复基线应使用固定镜像或其原始源码快照。

## 阶段 1：查询计算与选路

- 无过滤查询直接切片连续 float32 数组，省去整表布尔掩码和 fancy indexing 拷贝；分块复用同一 float64 临时缓冲，使用 NumPy `out=` 避免多份转换数组。
- 等值过滤结果按当前可见的不可变段签名缓存行号。与向量缓存共享 16 MiB 总预算，过滤缓存另限 1 MiB/32 项，更新和回滚通过原缓存失效机制切换数据版本。
- 批量距离只用于筛选候选；边界候选仍用 Python `math.fsum` 精确重算，保留原并列排序。缓存路径的 TopK 候选只保存距离、主键、行号；投影复用精排距离，仅在输出向量或计算其他距离时重建向量列表。
- 已有 Flat 索引时，小表同样尝试有界 NumPy 精确扫描。超过缓存预算时仍使用原磁盘 Flat；不删索引或跳过维护。

## 阶段 2：写入开销

批量执行 float32 转换与合法性检查，减少逐元素 Python/struct 调用；SQL 引号内文本按连续片段匹配，减少长向量字面量的逐字符正则分支。保留类型拒绝、溢出检测、失败语句原子性、BIGINT 全范围和转义规则。没有改变重复别名解析等原 SQL 行为。

## 阶段 3：Python 二进制存储

前两阶段无索引的写入/查询物理 I/O 仍各约 25.46 MiB，因此用 Python `struct`/标准文件接口实现并验证了不可变二进制段。新 `.mvb` 保存 float32 和类型化标量；主键、行位置合并在段尾，超过 256 KiB 时用有界临时文件缓冲。兼容旧 JSONL 读取和混合段，保持数据/索引落盘、清单原子发布、目录同步与成功响应的先后关系。超过缓存预算的宽行在解码前拒绝缓存，继续流式扫描或磁盘 Flat。

新格式已通过下文列出的强杀恢复、回滚、重启、索引维护和超过缓存容量测试。旧版 Python 不能读取新二进制段，基线和候选必须使用独立数据目录；新版本可以读取旧数据。

## 计量与保留条件

每轮 10000 行、128 维、1000 次 exact 查询、K=10，无过滤/等值过滤各 500 次，每批 100 行提交。写入、查询独立容器/父 cgroup/数据目录；查询装载、建索引、预热和写回计入 B/M；独立真值和完整持久化核验在采样结束后执行。计分关闭 profiling，不能拼接不同轮次最佳指标。

无索引逐阶段与前一版本交替对照，第一阶段的对照为原始 Python；所有比分均以同场景冻结 Python 基线归一化，并完整保留本轮资源快照。每轮独立计算 E，再取三轮中位数；仅报告 `E_local`。两组 exact Recall@10 必须都为 1，公开用例和回归必须通过。正式准入只由平台结果确认。

阶段 1 已通过 56 项 Python 回归、20 项官方公开用例及两种索引配置各 3000 次 exact 真值校验。无索引成对 E_local 中位数由原始 Python 的 0.507375 提升到 0.528784。

阶段 2 已通过 57 项 Python 回归和 20 项官方公开用例。无索引三轮中，其 E_local 均高于同轮阶段 1；中位数由 0.525557 到 0.529648。不同实验批次的对照波动不混用为同轮成绩。阶段 2 带索引测量和阶段 3 验收已完成，完整结果见下文。

### 最终验证

- 60 项 Python 单元/集成回归、20 项未改动的官方公开用例；正式隐藏 MySQL 准入没有重新提测。
- 最终镜像无索引/有索引各 3 轮，共 6000 次 exact 查询；无过滤和过滤组 Recall@10 全为 1，全部结果的距离、ID 与并列次序均核验。
- 旧 Python 镜像创建真实 JSONL/Flat 数据后由新 Python 读取；覆盖混合追加、回滚、重写、空段、重启、BIGINT 边界、Unicode、float32 极值和 17000 行段尾溢写。
- 6 个真实 SIGKILL 边界：行段同步前、索引同步前、清单同步前、清单替换前后、垃圾回收前；替换后恢复阶段再次强杀。测试钩子仅存在于独立测试镜像，未用于计分。
- 128 MiB 容器读取/修改 20000 行、156.25 MiB 标量负载，覆盖外排序、超过缓存容量的精确扫描/索引、回滚和两次强杀恢复。这是缩小内存压力验证，不能代替官方 2 GiB 全规模测试。

### 复现

源码快照与阶段日志位于 `.artifacts/python-optimization-20261114/`；固定基线在 `.artifacts/baseline-20261114-175804/`。源码哈希与镜像 ID 见 JSON。当前 Dockerfile 构建最终 Python 版本，依赖保持原 Python 3.12.8 / NumPy 1.26.4。

```powershell
docker build --platform linux/amd64 -t minivector-python:binary-20261114 .
./tools/run_performance.ps1 -Images 'input=minivector-python:input-20261114','binary=minivector-python:binary-20261114' -OutputDirectory '.artifacts/reproduce-python' -IoDevice '8:48' -Baseline '.artifacts/baseline-20261114-175804/performance/python.json'
```

有索引对照使用 `-CreateIndex`，并将 `-Baseline` 改为 `.artifacts/optimization-20261114/step3-indexed/python.json`。换机时先核对数据卷设备号并重新建立固定基线；旧机器指标不能直接作为新机器的对照。完整采样与复现条件见 [性能检测说明](../performance_checker/README.md)。

本地使用合成数据、Docker Desktop/WSL2、2 CPU/2 GiB，未清理宿主全局缓存。官方隐藏种子、硬件、冷缓存条件和冻结资源基线未复现，因此上述数值仅为 E_local，不换算赛事积分或排名。
