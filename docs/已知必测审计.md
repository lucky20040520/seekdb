## 本轮实际复现并修复的问题

1. 不同空表的cache key均为`()`，导致第二张空表复用第一张表的过滤列元数据，触发KeyError。修复为空表不建立无意义的向量缓存。
2. 比较常量错误地复用VARCHAR写入长度校验。修复为比较时保留类型及Unicode合法性检查，不将VARCHAR(n)的存储长度套到比较常量。更长常量可以正常得到空集或比较结果。
3. 只按K<=4096决定堆选择，导致宽行LIMIT累积全部宽记录。修复为同时估算完整候选行的内存占用，超过2MiB估算预算则使用磁盘排序。此预算不是总进程RSS或容器内存上限。

新增3项反例在修复前结果为2 errors + 1 failure；宽行反例的tracemalloc峰值为19,884,495字节，超出该测试12MiB阈值。修复后反例均通过。

随后补充跨表/向量/索引描述/失败语句/提交确认/强杀的组合检查，及Unicode长度、列顺序、极端float32边界。当前Windows完整34项检查通过，输出为`Ran 34 tests in 3.907s; OK`。新增测试不修改任何官方测试资产。
